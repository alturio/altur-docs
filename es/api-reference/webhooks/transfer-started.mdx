## Acerca de este evento

El webhook `transfer_started` se activa cuando Altur registra que inició la transferencia de una llamada. Úsalo para preparar contexto en tiempo real para el agente humano que podría recibir la llamada transferida.

## Detalles del evento

- **Trigger**: Se activa automáticamente cuando inicia la transferencia.
- **Propósito**: Notificar a tu backend o CRM antes de que conecte la llamada con el agente humano.

## Detalles de la solicitud

- **Método HTTP**: `POST`
- **Content Type**: `application/json`
- **Endpoint**: La URL que configures en tu integración de webhook.
- **Autenticación**: Incluye el header `X-Altur-Signature` para verificación HMAC.

### Campos de transferencia

| Campo                   | Tipo       | Descripción                                                        |
| :---------------------- | :--------- | :----------------------------------------------------------------- |
| `event_type`            | `string`   | `transfer_started`.                                                |
| `transfer_initiated_at` | `datetime` | Timestamp ISO de cuando Altur registró el inicio de transferencia. |
| `transfer_completed_at` | `datetime` | Normalmente `null` para este evento.                               |

Los demás campos coinciden con el payload de llamada de [`on_call_end`](https://docs.altur.io/api-reference/webhooks/on-call-end).

<Note>
  El payload describe la llamada en el momento de la transferencia: `status` es
  `in-progress`, `answered_by` es `human`, y `ended_at`, `ended_by`, `ended_reason`, `duration` y
  `billed_duration` son `null`. El `transcript` contiene los mensajes que Altur
  ha recibido hasta la transferencia; ocasionalmente pueden faltar las últimas
  líneas dichas justo antes de transferir. Usa `on_call_end` para el
  transcript completo. Los objetos `end_user` y `campaign_user` reflejan sus
  valores al momento de enviar el evento.
</Note>

Los webhooks de transferencia no admiten filtros.

## Respuesta esperada

Tu endpoint debe responder con 200 OK para confirmar recepción. Para el comportamiento de reintentos, consulta la [Retry Policy](https://docs.altur.io/api-reference/webhooks/overview#delivery-retry-policy).
